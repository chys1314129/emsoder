# 引用幻觉核查（cite-hallucination-check）

## 范围限定

本 skill 只核引用真实性（出处存不存在、引对没引对），不做错别字/排版/政治校对、不做行业数据采集、不做内容改写。

**安全边界**：只核验用户提供的引用，不自行生成引用、不代替用户做政治立场判断、不对外发布核验结果。联网检索仅用于事实溯源，不存储检索历史。

## 一句话定位

把"标【实证】前必核源真实存在"这条反幻觉纪律，做成一条**确定性核查管线**：
逐条引用 → 找真实出处 → 六组件比对 → 按规则判五类 → 出按严重度排序的红旗清单。

KPMG 翻车（45 条引用 40 条编造，2025-10 报告被撤）就是没跑这道关。本 skill 是这道关。

## 核心原则（不可豁免）

1. **证据，不是神谕**。本 skill 给的是"这条引用大概率有问题"的证据，不是终审判决。
   每条红旗都要给出"最相似的真实来源 + 哪个组件对不上 + 一句话理由"，让人能复核。
2. **宁可漏判，不可错杀**。把一条真引用误判成"编造"的代价很高（冤枉作者/甲方）。
   检索要尽量穷尽（本地源 + 联网）才下"编造"结论；查不到就走"无法核实"而非"编造"。
3. **联网取源是默认动作**。每条可核引用都要真去 `search(source="web")` 或 `fetch(type="url")` 或 `match(action="grep")` 本地源文件找原始出处，
   禁止凭记忆判断某来源"应该存在"。查不到证据时显式三选一：停-问 / 停-降 / 停-删。

## 五阶段管线

> **速览**：解析引用 → 分诊（可核/推理/不可核）→ 多源检索 → 组件比对 → 五类判定 → 红旗清单

### Stage 1 · 检测与解析

从用户输入文本 / `file_read` 读取的文件中直接抽取引用。

- **docx**：用 `file_read` 读全文，定位脚注、尾注、参考文献区、正文内 `[source: ...]` 标注。如遇表格/图片中的引用，逐页人工标注。
- **pdf**：用 `fetch(type="file_path")` 读取全文，注意脚注与超链接还原。扫描件告知用户需先 OCR 后重新上传。
- **md / txt**：用 `file_read` 读取，正则抓 `[source: 文件名:页/段]`、`【实证】… (URL)`、脚注、参考文献列表。

> 🛑 **检查点 1**：抽取完所有引用后，以列表形式向用户展示（序号 + 引用原文 + 六组件解析），询问："以上共 N 条引用，是否有遗漏或误抽？确认后进入核验。"

每条引用解析为**六组件**（咨询语境映射）：

| 组件 | 学术原义 | 咨询语境对应 |
|---|---|---|
| 标题 Title | 论文/书名 | 文件名 / 报告名 / 政策名 / 新闻标题 |
| 作者 Authors | 作者 | 发文机关 / 出品方 / 作者 / 受访人 |
| 出版方 Publisher | 期刊/出版社 | 发布平台 / 媒体 / 数据库 / 部委 |
| 日期 Date | 出版年 | 发文日期 / 文号年份 / 数据年份 |
| URL | 链接 | 链接 |
| DOI | DOI | 政策文号 / 档案号 / 标准号（如 GB/T…） |

### Stage 2 · 三路分诊

每条引用先分诊，只让"可核"的消耗检索资源：

- **可形式化核验**：有结构化组件（标题+作者/机关等）。→ 进 Stage 3。
- **需推理**：缺结构、或指向公认常识源（如"国家统计局公开数据""《宪法》"）。→ 用语义判断。
- **不可核**：设计上无法核验——"同上""内部访谈纪要（未公开）""与某领导座谈""甲方内部数据"。→ 直接判 `无法核实`，退出管线，**不算编造**。

> 🛑 **检查点 2**：分诊完成后，列出待联网检索的引用清单（序号 + 引用缩略 + 将使用的搜索词），标注涉密引用为「仅本地比对」。询问："以上将联网检索 X 条、本地比对 Y 条、跳过（不可核）Z 条。如有涉甲方真实名称/未公开数据的引用被误列入联网清单，请立即告知。确认后开始检索。"

### Stage 3 · 多源检索（默认主动联网）

对"可核"引用，按三路并行找候选真实来源，再合并排名：

1. **本地源比对**：用 `match(action="grep")` 搜索用户提供的 raw 源文件；用 `fetch(type="media_id"/"note_id")` 查知识库。
2. **权威库/接口**：政府网站、巨潮/年报库、国家标准全文库、官方统计公报、可信媒体。
3. **联网检索**：用 `search(source="web")` 以标题+机关+年份做定向搜索；用 `fetch(type="url")` 打开候选 URL 核对全文。

> 合规红线：涉甲方真实名称/未公开数据的引用，本地比对即可，**不要把客户机密词送进 `search(source="web")`**。

### Stage 4 · 上下文感知的组件比对

把原引用 vs 每个候选来源，逐组件打标。六组件，每对一个标签：
**match（对上）/ partial（部分对）/ not match（对不上）/ unknown（缺该组件）**；
作者组件额外支持 **weak match（弱对上）**。

关键：**不能只比字符串**。要结合语义——
"十四五规划纲要" vs "国民经济和社会发展第十四个五年规划纲要" 应判 match（同一文件简称）；
"2024 年中国 X 行业白皮书" vs "2023 年中国 X 行业白皮书" 一字之差但 not match（不同年份不同文件）。

### Stage 5 · 确定性 taxonomy 判定

组件分三层（诊断价值递减）：

- **Tier 1（关键）**：作者/机关、标题
- **Tier 2（强标识）**：URL / DOI / 文号 / 标准号
- **Tier 3（辅助）**：出版方/平台、日期

五分类规则（Agent 按以下确定性规则判定）：

- **真实可溯 exist**：(a) 作者与标题都 match；或 (b) 标题 match 且一方缺作者且至少一个 Tier2 match；或 (c) 公认极著名来源。
- **真实但有小错 exist-minor**：满足 exist，但有 Tier1-3 组件 not/partial；或一个 Tier1 match + 一个 Tier1 partial + 至少一个 Tier2 match + 无 not match。→ 来源真实，但引用需更正。
- **编造拼凑 fake**：(a) 作者或标题 not match；或 (b) 作者 weak match 且 Tier2 对不上/全 unknown 且出版方 not match；或 (c) 只有一个 URL 且链接坏/空页。
- **无法核实 unknown**：来源声明就不可公开核验；或信息太少（仅单组件）；或"同上"等。
- **存疑 unsure**：不满足以上任何一类的兜底。

> 🛑 **检查点 4**：五类判定完成后，先以简表向用户展示判定摘要（序号 / 引用原文缩略 / 判定类 / 一句话理由），对 `fake` 和 `exist-minor` 条目特别标注。询问："以上判定是否合理？确认后出完整报告。"

### 异常处理（各阶段 fallback）

| 阶段 | 如果… | → 则… |
|------|-------|-------|
| Stage 1 | 文本中找不到任何引用格式的片段 | 告知用户"未检测到引用"，展示扫描结果，请用户确认是否遗漏或直接粘贴引用文本 |
| Stage 1 | 引用信息残缺，六组件中 ≥4 个为 unknown | 标记该引用为「信息不足」，分诊时直接进「不可核」 |
| Stage 2 | 用户拒绝联网检索（涉密/合规原因） | 所有引用转为本地比对模式，无法本地核验的判 `无法核实`，不判 `fake` |
| Stage 2 | 所有引用都判为「不可核」（纯内部引用文档） | 输出空报告，说明原因，不强制检索 |
| Stage 3 | `search(source="web")` 返回 0 结果 | 换用不同查询词重试（标题简化/加年份/去特殊符号），至少 2 次尝试 |
| Stage 3 | `fetch(type="url")` 超时或返回 403/404 | 标记 url=unknown，用 `search(source="web")` 搜页面标题作为替代验证 |
| Stage 3 | 所有检索手段耗尽仍找不到任何候选来源 | 判 `无法核实`，不判 `fake`——缺证据 ≠ 编造 |
| Stage 4 | 两个候选来源的组件标签互相矛盾 | 优先采信权威来源（政府网站 > 新闻 > 博客），note 中标注矛盾 |
| Stage 4 | 语义比对无法确定简称/全称是否为同一文件 | 保守判 partial，标注"疑似同一文件简称差异"，不冒险判 match |
| Stage 5 | 某条引用同时满足 exist 和 fake 的条件 | 走保守侧——判 unsure 兜底，标注矛盾点供人工裁决 |
| Stage 5 | 多条引用指向同一来源但数据/表述不一致 | 逐条独立判定，不因同源统一归类，note 标注交叉引用关系 |
| 全流程 | 用户中途要求停止或修改核验范围 | 立即停止，展示已完成部分的阶段性结果，不强行完成全量 |

### Stage 3 检索策略（Agent 内联指南）

对每条可核引用，按以下策略逐类检索真实来源：

| 引用类型 | 检索方法 | 判定依据 |
|---|---|---|
| URL 链接 | `fetch(type="url")` 直接打开，检查 HTTP 状态码和正文长度 | 死链/空页 → url=not（触发 fake 路径） |
| DOI | 拼接 `https://doi.org/{DOI}`，`fetch(type="url")` 查 CrossRef | 无返回 → doi=not |
| 国标号（GB/T…） | `search(source="web")` 搜「{标准号} 国家标准全文公开」 | 找到官方记录 → 确认存在；找不到 → doi=not |
| A股年报 | `search(source="web")` 搜「{公司简称} {年份} 年报 site:cninfo.com.cn」 | 巨潮有记录 → publisher=match |
| 政策文号（国发/国办发…） | `search(source="web")` 搜「"{文号}"」精确匹配 | 政府网站有原文 → 确认存在 |
| 新闻/行业报告 | `search(source="web")` 搜「标题 + 出品方 + 年份」组合词 | 找到原文 → 逐组件比对 |

**保守原则**：网络失败/超时/不确定一律判 unknown，不凭一次失败判 absent。检索至少尝试 2 种不同查询词后才下「找不到」结论。

### Stage 4 完成后的 Agent 自检清单

进入 Stage 5 分类前，Agent 必须逐条自检以下项目。任一项 ERROR → 修正后才能 classify：

| # | 检查项 | 级别 | 规则 |
|---|---|---|---|
| 1 | 标签值有效性 | 🔴 ERROR | 所有组件标签必须在 {match, partial, not, weak, unknown} 内 |
| 2 | 回填完整性 | 🔴 ERROR | 可核引用 6 组件不能全为 unknown（表明检索未执行） |
| 3 | 红旗证据 | 🔴 ERROR | 预判 fake/exist-minor 的条目必须有 best_source（引用具体 URL/出处名） |
| 4 | 字段矛盾 | 🔴 ERROR | URL 死链时，url 组件必须为 not，不能留空或标 match |
| 5 | 薄回填 | 🟡 WARN | 可核引用 ≤1 个组件有标签 → 检索可能不充分，考虑追加搜索 |
| 6 | 红旗理由 | 🟡 WARN | 预判 fake/exist-minor 但 note 为空 → 补充一句话理由 |
| 7 | 证据缺失 | 🟡 WARN | 组件标了 not/partial/weak 但 note 未说明 → 补充证据描述 |
| 8 | 不可核原因 | 🟡 WARN | non-checkable 但 note 为空 → 填写不可核原因 |
| 9 | 噪声疑似 | 🟡 WARN | 引用原文 <6 字符 → 确认是否为有效引用 |

> 🛑 **检查点 3**：自检通过、进入 Stage 5 分类前，以简表展示每条引用的六组件标签（序号 / 引用缩略 / 组件标签摘要 / best_source）。对标签全 unknown 或 Tier1 组件 not match 的条目特别标注。询问："以上组件比对结果是否合理？确认后进入五类判定。"

## 输出

一张按严重度排序的**红旗清单**（fake > exist-minor > unsure > unknown > exist），严格按以下模板输出：

```markdown
# 引用核查报告

## 统计摘要
| 判定 | 数量 |
|------|------|
| 🔴 编造拼凑 (fake) | Z |
| 🟠 真实但有小错 (exist-minor) | Y |
| 🟡 存疑 (unsure) | V |
| ⚪ 无法核实 (unknown) | W |
| 🟢 真实可溯 (exist) | X |
| **总计** | **N** |

> 编造率：Z/N (X%)

## 红旗清单

### 🔴 编造拼凑
| # | 引用原文 | 最相似的来源 | 对不上的组件 | 理由 | 建议动作 |
|---|---------|-------------|-------------|------|---------|
| 1 | ... | ... | ... | ... | 停-删 / 停-降 |

### 🟠 真实但有小错
| # | 引用原文 | 真实来源 | 需更正的组件 | 理由 | 建议动作 |
|---|---------|---------|-------------|------|---------|
| ... | ... | ... | ... | ... | 更正组件后保留 |

### 🟡 存疑 / ⚪ 无法核实 / 🟢 真实可溯
（同上格式，按严重度递减排列）
```

每条含：引用原文 / 判定类 / 最相似的真实来源 / 对不上的组件 / 一句话理由 / 建议动作。

处置建议：判 `fake` 的引用，对应正文论断必须**停-删或停-降为【估算】+推算路径**；
判 `exist-minor` 的，更正组件后保留【实证】+ 修正 source；判 `unknown` 的，改为方法论描述或补料。

## 不做什么

### 范围级边界

- 不做错别字/语病/政治校对/排版 → `plan-proofread`
- 不做行业数据采集 → `industry-research`
- 不做去 AI 味改写 → `stop-slop-zh`
- 不判某段文字"是不是 AI 写的"；本 skill 只核**引用真实性**。

### Pipeline 阶段反模式

每阶段最常见的错误操作，必须避免：

| 阶段 | 🚫 反模式 | ✅ 正确做法 |
|------|----------|-----------|
| Stage 1 解析 | 凭印象"猜"这条引用可能指向什么来源 | 只从用户提供的文本中抽取引用原文，一字不改 |
| Stage 1 解析 | 跳过六组件解析，直接凭感觉判真假 | 每条引用必须拆齐六组件，缺组件标 unknown |
| Stage 2 分诊 | 把"内部访谈纪要"判为可核，浪费检索资源 | 设计上无法公开核验的引用直接判 unknown，不检索 |
| Stage 2 分诊 | 看到"国家统计局"就跳过核验，默认真实 | 即使公认来源，仍须验证具体数据年份/指标是否匹配 |
| Stage 3 检索 | 用一次搜索失败就判"找不到" | 至少尝试 2 种不同查询词后才下结论 |
| Stage 3 检索 | 把客户公司名/内部数据送进 `search(source="web")` | 涉密引用只在本地 `match(action="grep")` 比对 |
| Stage 4 比对 | 纯字符串匹配——"十四五规划纲要" vs 全称判 not match | 语义比对：同文件不同写法应判 match |
| Stage 4 比对 | 只看标题匹配就判 exist，忽略作者/年份对不上 | 六组件全部比对完才下判定 |
| Stage 5 判定 | 检索失败一次就判 fake | 网络失败一律判 unknown，不是 fake |
| Stage 5 判定 | 把 exist-minor 轻描淡写放过，不出更正建议 | exist-minor 也要出红旗，标注需要更正的组件 |
| 输出阶段 | 只列红旗不给相似真实来源，让人无法复核 | 每条红旗必须有 best_source + 对不上的组件 + 理由 |
| 输出阶段 | 用模糊措辞"可能有问题""建议核实"代替确定性判定 | 每条必须给出五类之一的确切判定 |

### 决策红线（做了就违规）

1. **不凭记忆判断来源存在**。即使你"知道"某政策/报告存在，也必须用 `search(source="web")` 检索确认。
2. **不在未穷尽检索时判"编造"**。至少尝试 ≥2 种查询词，至少检查 ≥2 个候选 URL，才可判 fake。
3. **不自行生成或补充引用**。用户没提供的引用，绝不代为添加或"完善"。
4. **不对外发布核验结果**。核验报告只返回给用户，不存储、不共享、不用于训练。
5. **不代替用户做政治立场判断**。只核引用真实性，不评价引用内容的政治倾向。
6. **不跳过 🛑 检查点**。检查点 1（解析确认）、检查点 2（检索确认）、检查点 3（比对确认）、检查点 4（判定确认）都必须等用户回复后才继续。

## ima 平台适配

本 skill 在 ima 平台运行时，不依赖外部脚本。所有管线阶段均由本 Agent 内联完成：

| 阶段 | ima 执行方式 |
|------|-------------|
| Stage 1 解析 | Agent 从用户输入文本 / `file_read` 读取的文件中直接抽取引用，解析六组件 |
| Stage 2 分诊 | Agent 按规则判定每条引用的可核性 |
| Stage 3 检索 | `search(source="web")` 联网 + `fetch(type="url")` 读候选 + `match(action="grep")` 本地 |
| Stage 4 比对 | Agent 逐组件语义比对，打标 match/partial/not/weak/unknown |
| Stage 5 判定 | Agent 按 taxonomy 规则分类，出五类判定 |

核心工具映射：
- 原 `WebSearch` → `search(source="web")`
- 原 `WebFetch` → `fetch(type="url")`
- 原 `Bash grep` → `match(action="grep")` / `file_read`
- 原 `cite_check.py` → Agent 内联执行（不依赖外部脚本）

### 安全排空

开场必问用户："涉甲方真实名称/内部数据的引用请标注，这些引用只用本地文件比对，不联网搜索。"

---

## 安全边界

1. **不送客户机密进联网搜索**。涉甲方真实名称/未公开数据的引用，只在本地用 `match(action="grep")` 核验，不送 `search(source="web")`。
2. **宁可漏判，不可错杀**。把一条真引用误判成"编造"代价很高——检索穷尽后才下"编造"结论；查不到走"无法核实"而非"编造"。
3. **证据不是终审**。每条红旗给出最相似来源 + 对不上的组件 + 一句话理由，人工复核后再删/改正文。
4. **verify 保守原则**：网络失败/不确定一律 unknown，绝不凭一次失败误判 absent/not。

---

## 已知边界

- `exist-minor` 类机检 recall 偏低（原方法实测约 45%），凡判此类务必人工再核。
- verify 保守原则：网络失败/不确定一律 unknown，绝不凭一次失败误判 absent/not。
- 涉甲方真实名称的引用，只在本地 `match(action="grep")`，不送 `search(source="web")`。
